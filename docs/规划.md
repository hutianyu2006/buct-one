> 适用基线：`v0.3.6`（`versionCode = 11`，包名 `com.buct.one`）｜Android：单 module Kotlin + Jetpack Compose（液态玻璃 UI）｜iOS 预览版：`:shared` Kotlin Multiplatform + Compose Multiplatform

### 1.2 核心工程底座

- **跨模块无感续期与校外 WebVPN 自动降级**：`SsoSilentRelogin` 单飞协调统一身份认证静默重登并统一全端 `sidportal` 请求 `User-Agent`；`BuctWebVpn` 对 7 个仅限校内的域名（`scs`、`eapi`、`ecard`、`gmis`、`i.buct`、`mnews`、`tree.buct.edu.cn`）按域名独立执行 3s 直连优先探测，校外受阻时自动通过 `w.buct.edu.cn`（Wengine AES-128-CFB）代理并支持原生短信 2FA 与 Keystore 票据持久化，校外可直连域名绝不走 WebVPN。
- **单向分层与 CI 门禁**：`ui → store/session/model`、`sync → source/store/session`、`source/*` 互不依赖、`model` 零外部 `import`；`check.yml` 强制扫描越层依赖与 TLS 校验。
- **全局预测性返回手势与轻量化工程底座**：全局启用 Android 14+ 预测性返回手势（跨 Activity 与应用内 `GlassSubpage` 二级页 / 弹窗跟手缩放联动，支持在设置中实时开关）；彻底清理非北化多校适配、好友社交、问卷与旧版空壳等约 1.7 万行历史冗余代码。
- **自托管匿名统计（`stats.buct.one`）**：基于自建 Umami + `OkHttp` + `BuctTlsTrustManager` + 随机 `UUIDv4` 统计每日活跃与模块热度，零第三方商业 SDK、零学号/个人敏感信息，支持在「我的 → 数据与安全」实时关闭。
- **分发与自动更新**：GitHub Release + Cloudflare R2 双源分发（`update.buct.one` / `dl.buct.one`），支持冷启动与「我的」页手动检查更新、ABI 匹配及 SHA-256 + 证书签名双重校验。

### 阶段四：双端共享（Kotlin Multiplatform + Compose Multiplatform）

> 原则：**能双端复用的逻辑只写一份**。数据模型与解析层已是最常改动的部分，优先迁移；Android 侧业务行为与 APK 内容保持不变。

1. **跨端底座（✅ 已落地）**
   - `:shared` 现在声明 `jvm()` + `iosArm64`/`iosSimulatorArm64` 三个目标：Android 以 JVM 变体消费（Kotlin 的 `androidJvm → jvm` 兼容规则，不需要 AGP、iOS CI 也不需要 Android SDK），iOS 以静态 `Shared.framework` 消费；
   - `commonMain` 只放平台无关逻辑，`iosMain` 放 Compose Multiplatform UI + Darwin 网络；`iosApp/` 仅 SwiftUI 壳；
   - CI：`code-check` 在 Ubuntu 跑 `:shared:jvmTest`（共享层单测）；`build` 的 `ipa` job 在 `macos-15` 先链接共享框架再 `xcodebuild`。

2. **已迁移的双端共享代码（✅ 已落地）**
   - **数据模型**：`com.buct.one.data.model` 全部 14 个文件（1.6k 行，零 import 约束不变）；
   - **解析层（10/10 全部共享）**：campusnet / card / electricity / jwnotice / mail / portal / scs / sjcx / theol / tygl 的纯函数解析器（约 3.2k 行）——Android 的 Client 直接调用同一份解析器，iOS 接好网络后同样复用；
   - **基础设施**：`data/json`（kotlinx.serialization 实现的 org.json 只读外观）、`data/text`（URL 编解码/解析、日期时间、HTML 实体）、Ksoup（jsoup 的 KMP 移植）；
   - **平台抽象层 `com.buct.one.platform`**：`KeyValueStore`（iOS 已提供 `UserDefaultsKeyValueStore`）、`AppLogger`、`AppScheduler`（协程）、`buildHttpClient`/`createPlatformHttpEngine`（Android OkHttp / iOS Darwin）、`AppCrypto`/`BuiltinCrypto`（纯 Kotlin AES-CBC/ECB、SHA-256、HMAC-SHA256、Base64，含 NIST/RFC 向量单测）；
   - **网络层（进行中）**：电费网关客户端 `ElectricityGatewayClient` 已下沉共享（Ktor + 共享 SHA-256 签名），Android 侧只保留注入校方 TLS/DNS 引擎的薄适配层；
   - **Cookie/会话（共享）**：`CookieStore` 抽象 + Ktor `HttpCookies` 适配器 `CookieStoreCookiesStorage`（域名/路径匹配），默认 `InMemoryCookieStore`；**会话 Cookie 视为短期凭据，默认不落盘**（与 Android `MatchingMemoryCookieJar` 一致，持久化必须走 Keystore/Keychain 加密存储）；双端各提供会话客户端工厂（Android `AndroidHttpClients.session`、iOS `createIosSessionClient`），并用"销毁再建客户端后 Cookie 仍可恢复"的 MockEngine 测试守护；
   - **iOS 登录界面（已落地）**：共享状态机 `CasLoginController`（Idle/Loading/Success/CaptchaRequired/SmsRequired/Failed）+ iOS 登录页（学号/密码、错误提示、可跳过先看公告），登录成功后首页展示会话状态与「退出登录」；Cookie 仅内存保存；
   - **CAS 密码登录流程（共享）**：`CasLoginPage` 解析登录页（flowkey/croypto/错误码/验证码/短信二次验证标记）、`CasLoginForm` 生成与校方前端一致的表单（密码 AES-ECB 加密）、`CasPasswordLoginClient` 完成 GET→POST→302/错误分类；Ktor 客户端支持 HttpCookies 与关闭自动重定向；用 MockEngine 集成测试验证了"表单加密可被解密还原 + 302 后 Cookie 自动携带 + 错误码/验证码分类"；
   - **统一认证加密（已完成）**：AES-ECB/PKCS7（`AesLoginCrypto`）与 **SM2 国密 + SM3**（`Sm2LoginCrypto`，基于 `com.ionspin.kotlin:bignum` 的纯 Kotlin 实现，C1C3C2 无 04 前缀格式与校方一致）双双下沉共享；Android 侧 `BuctAesCrypto` / `BuctSm2Crypto` 均改为委托。SM2 用 BouncyCastle 做差分校验（共享加密 → BC 解密），SM3 用 GB/T 32905 标准向量；
   - **单测**：共享层单测覆盖电费、校园网、提醒规则、AES/SHA/HMAC 向量、登录加密、日期/URL 工具，进 `:shared:jvmTest` CI；
   - **公告通道**：Ktor + kotlinx.serialization 复用 `notice.buct.one` 只读 JSON，iOS UI 已通电。

3. **剩余迁移清单（按依赖顺序，持续推进中）**
   - **登录与会话栈（iOS 能力的前提）**：加密原语与 CAS 密码登录主流程已共享；剩余短信二次验证、图形验证码拉取与 UI、WebVPN 自动降级、**Cookie/会话持久化**（`CookieStore` → Android SharedPreferences / iOS NSUserDefaults/Keychain）、Keystore → Keychain 会话 Vault，以及把 Android 的 `BuctSsoLoginManager` 改为委托共享实现；
   - **网络层收尾**：剩余 9 个域 Client（jwnotice / mail / portal / scs / sjcx / theol / tygl / campusnet / card）迁共享，依赖上面的 Cookie/会话/加密能力；
   - **存储与同步**：Store 改为面向 `KeyValueStore`（Android 侧补 SharedPreferences 适配器），Sync 改用 `AppScheduler`；
   - **UI**：给 `:shared` 增加 Android 目标（`com.android.kotlin.multiplatform.library`）后，把 Compose 页面从 `iosMain` 提到 `commonMain`，实现真正的单份 UI；
   - **强平台能力**：Keystore、小组件、预测性返回手势、自动更新、匿名统计需 iOS 等价实现，安全红线（全天候原生登录、凭据不落盘、禁止 trustAllCerts）不变。

4. **新增数据域的双端开发姿势（已生效）**
   - 解析器写在 `shared/src/commonMain/.../data/source/<域>`，只依赖 `data/json` 外观、`data/text`、Ksoup 与 `platform/` 抽象；
   - 样本单测写在 `shared/src/commonTest`，`:shared:jvmTest` 自动覆盖；
   - Android 侧只写网络/会话适配（Ktor 引擎需注入 `BuctTlsTrustManager`/`BuctDns`），iOS 侧等网络层迁移完成后零改动即可获得同一解析与请求能力。

## 三、开发准入规范、已调研边界与「不做」清单

### 新模块接入自查表

1. **认证**：必须全原生 Kotlin + OkHttp，禁止引入 WebView 登录流程。
2. **分层**：严格遵守 `model（零 import）← store ← source（子包隔离）← sync ← ui`，合入前过 `check.yml` 静态检查。
3. **铁律**：失败永不覆盖旧 `data`、`NEVER != EMPTY_CONFIRMED`、改解析器必递增 `parserVersion`、更新时间戳 `capturedAt` 单调不减。
4. **安全与体积**：全走 `BuctTlsTrustManager` + `BuctDns`；独立凭据必须用独立 `KeystoreCipher` alias 并列入 `backup_rules.xml` / `data_extraction_rules.xml`；严控依赖增量以防触发 80MB 预警 / 100MB 门禁。

### 已实测排除与明确不接入范围

以下系统已完成实测或抓包调研，结合可行性、用户体验与单人维护边界明确不予接入，避免后续重复踩坑：

- **北化校园卡小程序（`mcardtoo.buct.edu.cn`）及外部直跳**：
  - 抓包实测 `mcardtoo.buct.edu.cn` 强依赖微信 `wx.login()` 换取 64 位十六进制 `openid`、一卡一微信强绑定且全链路 `datajson` 随机加密，原生 App 接入不仅无法走通登录，还存在顶掉用户微信绑定的风险；
  - 实测学校未在微信小程序后台配置明文 URL Scheme 白名单（拉起报「当前页面无法访问」），且个人开源 App 无法通过微信 OpenSDK 获取跨主体管理员授权；
  - 另实测 `i.buct.edu.cn` 的 `getYktOrBook.jsp?type=ykt` 不返回余额字段（门户页面自身显示 `NaN`）。因此校园卡坚持 `ecard.buct.edu.cn` 原生路线，不做付款码 / 水电小程序代登或假直跳按钮。
- **信息门户整站 UI 与办事大厅（`service.buct.edu.cn`）**：
  - 门户应用中心与办事大厅（证明开具、返校审批、流程待办等）属于低频重表单事务，校内师生常规在企业微信处理；App 内只拆取校历 / 教学周、通知公告与图书在借等高频轻量接口，不搬运办事大厅表单或重写门户界面。
- **数字导航中的独立低频子系统**：
  - 后勤公寓与 2833 报修（`repair.buct.edu.cn`）、我的财务（`cwmh.buct.edu.cn`）、i学生（`ixg.buct.edu.cn`）与独立图书馆 OPAC 系统（`lib2.buct.edu.cn`）均不接入，保持界面克制与单人可维护规模。

### 明确工程红线

- **不做 WebView 登录或跨端 Web 壳**（Capacitor / RN 等）。
- **不做无人值守全自动抢课或高风险自动化写操作**（如代打卡、代交答案、自动抢购），仅保留合规查询、手动确认操作与本地闹钟 / 通知提醒。
- **不做任何第三方商业行为埋点、崩溃上报 SDK 或广告组件**（仅保留可由用户随时关闭的自托管 Umami 零 PII 匿名活跃统计）。
- **不引入高体积离线大模型 / OCR / 重型地图 SDK**，保持客户端轻量、快速启动与可控包体。
